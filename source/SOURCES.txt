BT PAN (EL71 / E71 sw45): что где лежит в исходниках
================================================

Общая схема
-----------
Эльф - сетевой драйвер, не прокси. Телефон подключается к ПК по Bluetooth как PANU
(L2CAP PSM 0x0F, BNEP), а встроенный IP-стек телефона (ENIP) получает новый интерфейс.
Через него идут IP-пакеты целиком: один IP-пакет = один кадр BNEP = один кадр L2CAP.
Браузер, Java и эльфы ходят в сеть обычными сокетами.

Процессы:
  MMI (CSM эльфа)       экран, кнопки, настройки, TCP-спидтест (таймер)
  0x1A00 "BTPAN"        всё Bluetooth: аксессор BTA, канал L2CAP, BNEP, приём из кольца,
                        DHCP, сторож приёма, прямой спидтест, список устройств
  0x440A (ElfLoader)    помощник для сокетов эльфа (SUBPROC): TCP-спидтест;
                        к нему же "прикреплены" наши LMAN-контексты
  0x40B4 ENIP           стек телефона; наш драйвер зовётся из него (отправка пакетов)

Путь пакета:
  отправка: ENIP -> bt_pan_netif (кадр BNEP) -> bt_panu_send -> SDev fn[2] -> L2CAP
  приём:    L2CAP -> sdev_rx (колбэк стека, чужой процесс) -> кольцо 32 КБ ->
            таймер 0x1A00 (~23 мс) -> BNEP -> bt_pan_netif_input -> ENIP

src/ - эльф
-----------
main.c          Точка входа и жизненный цикл.
                - main(): COM-лог, pan_lman_init, загрузка настроек, процесс 0x1A00, экран.
                - Настройки BCFG: структура PAN_CONFIG (адрес ПК, имя ПК, автопереподключение),
                  файл ?:\zbin\etc\BTPAN.bcfg: config_load/config_save/config_apply,
                  save_peer_addr (из списка устройств), set_auto_reconnect.
                - process_messages(): обработчик процесса 0x1A00, сообщения 0x6B4D..0x6B54
                  (старт, события BTA, стоп, список устройств, прямой спидтест).
                - AppStartPan/AppStopPan, begin_shutdown/finish_poc: включение и полное
                  выключение (с возвратом слотов SDev); после отключения эльф остаётся.
                - rx_watch(): сторож приёма раз в 5 с (ARP к ПК при тишине 10 с, отчёт и
                  "пинок" на 20 с, переподключение на 30 с - если включено в настройках).
                - hooks_patch_state(): проверка врезок во флеше (патч из patches/).
                - pan_server_ip(): адрес ПК (DHCP-сервер) для спидтестов и ARP.
                - BT_PANU_RUN_SECONDS (config.h): связь сама выключается через 1 час.
app_ui.h        Экран (подключается в конец main.c).
                - Вкладка "Связь" (DrawLink/LinkItems, прокрутка): статус, IP, кнопка
                  Подключить/Отключить, "Компьютер" (список устройств), автопереподключение,
                  ПК/шлюз/DNS, счётчики трафика.
                - Вкладка "Тест" (DrawTest/DrawResult): два спидтеста с прогрессом.
                - Список устройств (DrawPicker, PickerOpen/PickerClose).
                - Клавиши gui_onkey; перерисовка UiPoll по "подписи" UiSig (не чаще 3 раз/с);
                  CSM: maincsm_onmessage (события сокетов TCP-теста, перечитывание BCFG),
                  maincsm_onclose (выключение перед выгрузкой эльфа).
config.h        Константы: IP по умолчанию, MTU для стека (BT_PAN_MTU), номер интерфейса и
                bearer драйвера, DHCP вкл/выкл, лог каждого пакета, MTU канала L2CAP.

bt_sg.h          S65 sw58 (SGOLD): CA-слой вместо BTA (MR, L2CAP_New, Conn_Close) по
                  фиксированным адресам, проверка прошивки; используется под #ifdef SGOLD.
bt_panu.c/.h     Bluetooth-канал (PANU).
                - SDev: на время работы своё приложение в слотах SDEV_APPS[0x0F] и [0x05]
                  (sdev_open/sdev_rx/...; bt_panu_install_app/bt_panu_restore_app).
                  Из-за этого Java по Bluetooth (JSR-82) недоступна, пока эльф работает.
                - Подключение: аксессор BTA, BTA_Conn_New_L2CAP на PSM 0x0F, запрос
                  BNEP setup (bt_panu_send_setup), ответы на BNEP filter-запросы ПК.
                - Приём: sdev_rx кладёт кадры в кольцо rx_ring; bt_panu_poll_rx/
                  bt_panu_drain_ring разбирают его; bt_panu_deliver просит стек прислать
                  придержанные кадры. Счётчики и отчёт для сторожа: bt_panu_rx_count/
                  bt_panu_rx_report/bt_panu_rx_kick.
                - Отправка: bt_panu_send (целый кадр или ничего; своей очереди нет).
                - Закрытие: bt_panu_stop/bt_panu_close_step - ждать, пока пул отправки
                  вернётся (иначе буферы теряются до перезагрузки), потом закрыть.
bt.h            Типы и макросы Bluetooth API прошивки (аксессор, события, BD_ADDR, SDev).
sapp.h          Структуры SApp/SDev (интерфейс приложения последовательного устройства).
lib.h/lib.c     Функции и данные прошивки берутся из библиотеки функций (LIB_ENTRY(номер),
                номера 420-471 как в SDK swilib). lib_check при запуске проверяет, что все
                нужные записи в библиотеке есть.
bnep.c/.h       Формат BNEP: сборка кадров, разбор входящих, setup/filter.
arp.c/.h        Ответ на ARP-запросы ПК.
dhcp.c/.h       DHCP-клиент: DISCOVER/REQUEST, разбор OFFER/ACK (IP, шлюз, DNS).

bt_pan_netif.c/.h  Сетевой интерфейс в стеке телефона.
                - Регистрация драйвера ENIP (bearer 1, интерфейс 1), MTU, IP, DNS.
                - bt_pan_netif_send_ipv4: пакет из ENIP -> кадр BNEP -> bt_panu_send;
                  пакеты > 1500 отбрасываются; в лог - окно/MSS наших TCP SYN.
                - bt_pan_netif_recv: из BNEP: IPv4 -> ENIP, ARP -> ответ, до получения IP -
                  только DHCP.
                - DHCP по шагам и подъём интерфейса (bringup -> pan_lman_up).
                - bt_pan_netif_send_frame: отправка готового IP-пакета из любого процесса
                  (прямой спидтест); bt_pan_netif_arp_probe: ARP-запрос к ПК (сторож).
                - Счётчики bt_pan_rx_bytes/bt_pan_tx_bytes для экрана.
enip.h          Структуры стека ENIP прошивки (модуль, драйвер, порт, пакет) и вызовы
                enip_* (адреса EL71 и E71).
icmp_probe.c/.h Один ICMP echo к ПК после подъёма (проверка связи в логе).

pan_lman.c/.h   Чтобы приложения телефона шли в сеть через наш интерфейс.
                - Приложение просит профиль GPRS (NAP) -> pan_prepare создаёт LMAN-контекст
                  с именем профиля, привязывает к нашему интерфейсу, состояние "подключено".
                  Приложение должно получить самый младший свободный cid (с cid 2 браузер
                  портит память и падает).
                - Где ловится запрос: Java (сообщения 6245/6246) и HTTP_DOWNLOAD (6240) -
                  подмена обработчика процесса (java_hook/http_hook); встроенный браузер
                  (WSP) и эльфы - врезки во флеше (патч из patches/), которые находят наши
                  функции через "шлюз" pan_gateway в обработчике ENIP (метки BTN1/2/3):
                  before_connect, wsp_online, wsp_bearer.
                - enip_hook: лог запросов socket/dns/connect с владельцем и ошибкой.
                - pan_self_context: постоянный контекст "BT PAN" для помощника ElfLoader
                  (сокеты эльфов: BalletMini, наш TCP-тест), всегда на cid >= 2.
                - DNS: заполняет таблицу резолвера A8E9E9CC[интерфейс], пока связь есть,
                  потом возвращает как было.
                - pan_lman_up/pan_lman_down: включить/снять всё это; contexts_release
                  рассылает отключение владельцам; pan_lman_poll - лог раз в секунду.

peers.c/.h      Список сопряжённых устройств для выбора ПК: свой временный аксессор BTA в
                процессе 0x1A00, только пока связь выключена (BTA_DeviceListView_*).
ping.c/.h       Пинг ПК (вкладка Ping): эльф сам собирает ICMP echo раз в секунду и шлёт прямо
                  в BT (как прямой спидтест, процесс BTPAN), ответ ловится до ENIP (ping_rx).
                  RTT по таймеру STM (F4B00000, 26 МГц/RMC; одинаков на PMB8875/8876), потери,
                  история 32 ответов. Размер 56/512/1472, не больше IP MTU - 28 (S65 без патча
                  292). Хост-тест: tests/test_ping.c (сборка в комментарии).
speedtest.c/.h  Два спидтеста против speedtest-pc.py (по 6 с приём и отдача).
                - Прямой (d_*): процесс 0x1A00, эльф сам собирает UDP 1472 байта и шлёт в
                  канал; поток с ПК (UDP 5001 -> 5002) перехватывается до стека
                  (speedtest_direct_rx). Меряет сам Bluetooth.
                - Через стек (s_*): обычный TCP-сокет (порт 5003) в помощнике ElfLoader,
                  события сокета приходят в CSM (speedtest_stack_msg). Меряет то, что
                  видят приложения.
usart.c/.h      Отладочный COM-лог 115200 (usart_puts под LockSched: пишут несколько
                процессов).
freestanding.c  memset (в SDK его нет).
BT_PANU.md       Старые заметки по первому PoC (частично устарели).

Сборка и прочее
---------------
CMakeLists.txt       Сборка эльфа (SDK ../sdk), список исходников, номер сборки.
bump_build_id.cmake  Перед каждой сборкой +1 к .buildnum -> build/build_id.h
                     (BT_PAN_BUILD_TAG "Dxx": шапка экрана и первая строка COM-лога).
.buildnum            Текущий номер сборки.
tests/test_dhcp.c    Проверка формата DHCP на ПК (gcc, без телефона).
nap.sh               ПК: мост pan0, NAT, DHCP (dnsmasq), NAP-сервер BlueZ, сервер спидтеста.
speedtest-pc.py      ПК: сервер спидтеста (UDP 5001, TCP 5003).
bt-pan-mtu.vkp       Патч MTU 1500 для Bluetooth (обязателен), EL71.
bt-pan-mtu_E71v45.vkp  то же для E71 (port-mtu-e71.py)
e71/find-e71.py      поиск адресов E71 по дампу -> e71/map.tsv
