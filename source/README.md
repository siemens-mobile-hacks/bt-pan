# bt-pan — интернет на телефоне через Bluetooth PAN

Эльф для BenQ-Siemens EL71 sw45 и E71 sw45 (и S65 sw58, см. ниже). Телефон подключается к ПК по Bluetooth PAN, ПК
раздаёт интернет. Браузер, Java и эльфы ходят в сеть как через GPRS.

Основан на PoC от ARMenian Developer.

## Сборка
```sh
cmake -B build -S . && cmake --build build
```
Получаются `build/bt-pan_ELKA.elf` (EL71/E71 sw45), `build/bt-pan_SG.elf` (S65 sw58, SK65 sw50),
`build/bt-pan_NSG.elf` (S75 sw52) и `bt-pan_ELKA_P60.elf` (процесс BTPAN с приоритетом 0x60, для сравнения).
Один исходник, отличия под `#ifdef SGOLD`. Логов, трассы и отладочных счётчиков нет (D152).

## Экран
С D131 — меню прошивки (CreateMenu, как ncdu/etabdemo/s65-player), своего рисования нет.
- Главное «BT PAN Dxxx»: Connect/Disconnect, Status, (подсказка про патч хуков), PC (выбор из
  сопряжённых), Auto-reconnect, при подключении IP / Gateway / DNS / MTU, Received и Sent со
  скоростью, Speed test..., Ping..., Minimize, Exit. Левый софт/центр — действие строки, зелёная —
  подключить/отключить, правый софт — выход (с отключением), красная — свернуть.
- С D153 два CSM: демон без GUI ниже idle (таймер, сообщения MMI, выход) и экран сверху. Экран может
  закрыть кто угодно (красная на чужом экране = DoIDLE, звонок, сон S65) — связь остаётся; повторный
  запуск эльфа открывает экран снова. Выгружает эльф только Exit.
- «Speed test»: Direct (BT, UDP) и Via stack (TCP): старт/стоп, прогресс, скорость вниз/вверх.
- «Ping»: старт/стоп, размер 56/512/1472, адрес, последний, ответы, потери, среднее, мин–макс,
  последние 8 RTT в мс (x = потерян). Правый софт — назад (пинг идёт дальше).
- «Choose PC»: сопряжённые устройства (имя и MAC).
Живые значения: таймер MMI 0,25 с сравнивает числа (без sprintf) и обновляет только меню сверху:
смена состояния — сразу, счётчики — не чаще раза в секунду; свёрнутое/закрытое не трогается.
Проверка экрана без телефона: `tests/emu_ui/run.sh` (настоящий `src/app_ui.h` над поддельным PAN в
elfloader3-linux, снимки в `tests/emu_ui/build/shots/`). На ПК файрвол не должен резать ICMP.

## S65 sw58 (SGOLD)
Проверено на телефоне (D86–D90): подключение к ПК, пинг, Opera Mini (Java), встроенный браузер.
D91 (функции CA и регистрации LMAN из библиотеки) на телефоне ещё не проверен.
- Библиотека: `library-s65-sw58-extended.vkp` (база 10897 + 138 записей) или поверх уже
  прошитой 10897 — `library-s65-sw58-10897-addon.vkp`. Эльф берёт из неё все функции прошивки,
  в том числе Bluetooth CA (4CD–4DE) и регистрацию LMAN (4DF–4E0). Без них пишет
  "install the function library".
- Bluetooth: на S65 нет слоя BTA, эльф работает с объектами CA, как Java (JSR-82), `src/bt_sg.h`.
- MTU: эльф сам смотрит, стоит ли `bt-pan-mtu_S65v58.vkp` (генератор `port-mtu-s65.py`). С патчем:
  L2CAP 1691, IP 1500, DHCP, стеку сообщается MTU 3000 (окно TCP для Java), ПК: `sudo ./nap.sh`.
  Без патча: L2CAP 335, IP MTU 320, ПК: `sudo MTU=320 ./nap.sh`, адрес статический 192.168.7.2.
- Java и браузер: LMAN переиспользует контекст, на который ссылается регистрация сокетов
  вызывающего. Эльф держит свой контекст (bearer 1, наш интерфейс, состояние 4) и даёт на него
  ссылку всем регистрациям (хуки HTTP 4409/4403 и LINKMANAGER 40DD, опрос раз в секунду);
  отправителя LINKMANAGER msg A без регистрации (браузер 4402) регистрирует сам до обработки.
- Встроенный браузер без SIM: `bt-pan-browser_S65v58.vkp` (генератор `port-browser-s65.py`).
  Проверка канала браузера (A0B715CC) видит «зарегистрирован в сети», пока шлюз эльфа в
  обработчике LMAN сообщает, что наш контекст готов; без эльфа — штатно.
  v2 (2026-11-15, на телефоне не проверено): та же проверка требует непустой APN в GPRS-профиле
  данных текущего профиля браузера (A0B71568, вызов A0B71610); без SIM он пуст -> «сеть недоступна».
  Пока bt-pan готов, вызов A0B71610 идёт в заглушку A0D9FE80 (в пределах BL, без переходника) и
  отвечает 1. `bt-pan-browser_S65v58.vkp` — полная v2 для стока, `bt-pan-browser-apn_S65v58.vkp` —
  только добавка поверх прошитой v1. Заглушки проверены в unicorn (готов/не готов/нет шлюза/proc 0).
- Пакеты стек отдаёт драйверу, драйвер отправляет их сразу в процессе ENIP (не через помощника
  ElfLoader: тот голодал, пока Java опрашивала DNS). Процесс BTPAN — приоритет 0x60.

## SK65 sw50 (SGOLD)
Тот же `bt-pan_SG.elf` (D92+): прошивку (S65v58 / SK65v50) эльф узнаёт по записи библиотеки
4D6 (`bt_sg_fw()` в `src/bt_sg.h`) — от этого зависят только проверка MTU-патча и адрес DNS для
трассы. На телефоне не проверено. Всё для установки — `release-sk65/`:
- Библиотека: `library-sk65-sw50-extended.vkp` — один файл со всеми функциями (база avkiev 7546 + bt-pan +
  перенос всей библиотеки S65v58, 862 записи, = `swi.blib`). Нужен ElfPack 3.3.2 (даёт 171/172, 2FE/2FF, 400).
  Как найдены записи — `signatures/SK65.md`.
- MTU: `bt-pan-mtu_SK65v50.vkp` (генератор `port-mtu-sk65.py`) — те же места, что на S65 (11 строк), но
  PB=0 исправлен на месте (3 инструкции в BTLSAR), без заглушки: свободный флеш дальше 4 МБ от BL.
- Браузер без SIM: `bt-pan-browser_SK65v50.vkp` (`port-browser-sk65.py`): 8 байт в проверке
  A073F21E заменены дальним переходом на заглушку A10FFE00.
  v2 (2026-11-15): та же проверка требует непустой APN в GPRS-профиле данных текущего профиля браузера
  (A073F1BA = S65 A0B71568); на телефоне, где SIM никогда не было, APN пуст -> «сеть недоступна».
  Пока bt-pan готов, проверка APN тоже проходит (вызов A073F262 -> 8-байтный переходник в трассовой
  строке A073FC84 -> заглушка A10FFE80). Файлы v1 и apn-добавки удалены 2026-11-15
  (на телефоне прошита полная v2). Без патча то же лечится вводом
  любого APN в профиле данных. На S65 v1 проверялась с SIM (APN был задан); без SIM — та же ловушка.
  v3 (2026-11-15): A073F1BA на деле проверка канала CSD (v2 вела браузер по CSD). v3 оставляет её
  стоковой и обходит проверку GPRS-канала (вызов A073F252 bl A073F1EE -> тот же переходник -> заглушка
  A10FFE80 с литералом A073F1EF). `bt-pan-browser_SK65v50.vkp` — полная v3 для стока,
  `bt-pan-browser-gprs_SK65v50.vkp` — добавка поверх прошитой v2. Тест: `tests/emu_browser_sk65.py`.

## S75 sw52 (NewSGOLD без ELKA)
Своя сборка `bt-pan_NSG.elf` (экран 132x176; D151+, прошивка по 46A = A0999073).
На телефоне не проверено. Всё — в `release-s75/`:
- `library-s75-sw52-extended.vkp` — полная библиотека (8285 + 54 записи для bt-pan и radio), `swi.blib`; нужен
  ElfPack 3.3.2.
- `bt-pan-mtu_S75v52.vkp` (`port-mtu-s75.py`): места EL71, PB=0 исправлен на месте, кольцо JSApi — A15BF400.
- `btnet_S75v52.vkp` (`port-browser-s75.py`): врезки браузера, как на EL71, диспетчеры A15BF800/FC00/FE00.
Адреса и как найдены — `S75-PORT.txt`; тесты `tests/emu_mtu_s75.py`, `tests/emu_hooks_s75.py`,
`tests/emu_ui` (`PLATFORM=NSG ./run.sh`).

## Запуск
1. Поставить патчи из релиза: `patches/` (EL71), `patches/e71/` (E71) или `patches/s65/` (S65).
2. ПК: `sudo ./nap.sh`
3. Телефон: запустить эльф, выбрать ПК, "Connect".

Что в каком файле — `SOURCES.txt`.
